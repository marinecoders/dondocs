# Maintaining package templates

Open **Maintain package templates** and choose a maintained or saved versioned starter. **Edit a separate template revision** loads its existing questions, native documents and field targets. Change the template name and revision label, edit question labels and types, and use **Document field mappings** to connect questions to supported empty native fields.

**Conditions, groups and document declarations** exposes the existing typed JSON declarations for conditional questions and membership, repeated people, choice options and operation requirements. Declarations contain no executable expressions. Keep identities stable when preparing a controlled upgrade. Invalid targets, incompatible answers, prior signatures and populated linked fields fail the existing template qualification checks.

Add synthetic intake scenarios and independently choose their expected document instances. The expectation is compared with the evaluated conditions; it is not copied from the actual result. Supply a fresh synthetic PDF when a scenario activates an evidence slot. **Validate template scenarios** runs the same preparation used by normal intake, without saving an action or sample file. A saved maintained template needs complete scenarios, matching expected membership, every question exercised, and both outcomes of each conditional declaration. Up to twelve scenarios and 64 MB of sample files can be checked together.

Review the retained starter text, figures, declarations, mappings and privacy findings before **Save reviewed template revision**. Saving creates a separate library entry; existing packages retain their exact captured template. Sample answers and files are excluded from the library entry. Policy changes, cancellation or a superseded editor require another review. Switching to read-only cancels pending writes and invalidates the scenario review; local declarations remain available to discard. End users continue to select the finished action through the normal intake workflow.

## Adopt a newer template

In a current owning package, open **Template and form upgrades** and load the selected newer template. Map each prior question and document slot, or preserve it independently. Mapped questions retain their answer type and participant group. The existing main document maps to the new main slot, keeping its exact current text. New starter text never replaces an existing document body.

Review the target intake answers and fresh file slots. Confirm preservation, then **Preview template adoption**. Resolve membership, shared-answer and field conflicts through the existing intake decisions. Apply only after reviewing the change-impact report and retained privacy findings. Independent files, facts, local overrides and review history remain; new template-controlled requirements require fresh review.

Each adopted revision carries an immutable receipt with the prior exact template source, raw and applied answers, mappings and previous requirements. Inactive and unmapped answers therefore remain available even in selected-revision editable transfers. Up to ten retained upgrades fit within the existing conditional-state and history budgets. Later intake edits retain and review these captured older sources as well.

## Migrate a configured form separately

Choose **Migrate one form definition**, a captured configured form and the exact replacement blueprint from the loaded template. Review the explicit field, option and repeating-group migration. Every existing answer needs a unique destination accepted by the existing form migration engine. Choose whether each affected package link should be remapped, kept as a local override or detached.

**Preview form definition upgrade** shows before/after answer values, including repeated rows, exact template pages and package impact. Incompatible shared values need a deliberate local override or detachment. Signature answers remain only in the original history after explicit acknowledgement; upgraded signature fields stay blank. Apply the reviewed migration to a new revision. It preserves original drafts and PDF backgrounds and does not adopt the newer template's membership automatically. Unmapped or ambiguous content, changed policy, cancellation and newer package work stop the operation.

**Inspect retained starter text and assets** opens a selected exact background PDF or figure in a read-only preview. Inspect the retained pages and figures as well as searchable text before approving a template or definition change.

## Create independent actions from a roster

Open **Packages from a roster** and load a maintained or saved versioned template. Import an Excel `.xlsx` workbook using the existing local roster reader, select its header row and map the action name, questions and participant groups. **Inspect or correct mapped worksheet cells** preserves the original import warnings until you deliberately edit a cell. Use `YYYY-MM-DD` dates, exact choice IDs and `true`/`false` or `yes`/`no` boolean answers. Repeated people use a JSON list of `{label, answers}` entries; every action receives fresh participant identities. You can also **Add fresh action row** without a workbook.

Review and correct each action's name and intake answers, then supply fresh PDFs for that row's active slots. Answer changes clear that row's uploaded PDFs. Inspect the exact supporting pages through the row's preview button. A source row never inherits another row's files, local links, signatures, review decisions or tasks.

**Preview roster actions** prepares the real independent actions without saving packages or attachments. Correct all invalid rows before reviewing and saving the local creation inputs. Saving these inputs creates no action and stores no review acknowledgements. Choose a saved action row, review its document changes and privacy findings, then **Create independent package**. Each successful package and its row receipt are written atomically. Existing completed rows remain clear if a later row fails or an operation is cancelled.

After reload, **Refresh saved rosters**, choose the saved journal and **Resume saved roster review**. Remaining rows need fresh review under the current deployment policy. Completed rows open their existing owning action; they are never recreated automatically. Later work in an action remains independent. Open a created action to use the normal PDF delivery and resumable assembly-job controls.

The producer supports up to 25 actions per roster, four saved journals and 128 MB across their captured inputs. Each journal and its combined prepared creation files have separate 64 MB limits; exact repeated template captures count toward the preparation limit. Existing 25 MB PDF and template limits also apply. Split larger jobs into smaller rosters.

Roster journals remain local to this browser and are excluded from package and workspace backups. Created actions use normal package transfer and recovery. Removing saved roster inputs leaves every created action intact. **Discard roster preparation** closes the local view without removing a saved journal.
