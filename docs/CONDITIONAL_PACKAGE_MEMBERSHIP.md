# Captured action intake and membership

Conditional actions own an exact version 2 template JSON asset. Every saved intake revision references its authenticated bytes, so reload, backup, review and editable transfer do not depend on the current template library. A newer template is never adopted implicitly.

`saveConditionalPackageDraft` saves raw unfinished answers separately from the last applied answers. Existing documents, shared information and field links remain untouched. Pending intake is explicit and blocks PDF assembly and review; portable editing can preserve unfinished work.

`prepareConditionalPackage` owns all supplied answers, decisions and file bytes before asynchronous work. It evaluates bounded declarations, preserves participant/member identities through reorder, and stages new native drafts and original PDFs without writing storage. Unknown branches are unresolved. Required missing files remain slots rather than fabricated documents.

An unchanged generated document can leave a branch automatically. Edited native documents and independently supplied originals need a keep/remove decision. A manually removed document needs an explicit restore decision before regeneration. Local exceptions and deliberately detached links remain local. Initially unanswered optional fields retain their exact target identities, including fresh configured-form row identities, for a later answer.

Intake merges newer package information when an answer was unchanged. Overlapping changes require a current-package/intake decision. Clearing an applied optional answer requires a decision about existing linked document values; it cannot silently reappear on resume. Hidden retained answers never control branch selection.

Applying requires the privately issued preview, explicit review, current deployment policy and unchanged package ownership. A single transaction writes the child revision and all referenced assets. Cancellation, quota failure, stale ownership or policy changes preserve the prior complete package. Undo creates another child revision, restores the prior package name and content, and refuses to overwrite intervening work.

Disclosure review includes raw inactive answers, every template branch, retained starter text and PDF backgrounds. Exact source, answer, document and field mappings are checked during transfer and recovery. Captured metadata describes an association; it does not authenticate a person or create signing or review authority.
