# Captured package field links

`PackageRevision.bindings` holds optional version 1 link metadata alongside captured package information. A link names one fact ID, one member ID and one qualified native target. It records the last applied scalar value, an explicit formatter, and linked or local-override mode. It grants no authority to an editor, source document or signer.

Supported targets are whole active correspondence headers, declared scalar fields in the two built-in forms, and text, identifier, date, decimal, boolean and single-choice answers in configured forms. Configured targets pin form ID, definition/template revisions and the definition's SHA-256. Repeating answers use group and row IDs, never row positions. Duplicate row identities are unavailable. Signatures, multiple-choice arrays, paragraph text, technical publications, unknown kinds and original PDFs are unsupported. Targets never accept arbitrary object paths.

`listPackageBindingFields` and `resolvePackageBindingTarget` read captured models. `formatPackageFactForField` preserves lexical identifiers and decimals and requires compatible answer kinds. Configured dates retain ISO dates. Supported legacy native date fields use the established `d MMM yy` convention and reject years outside 2000–2099. Uppercase formatting is an explicit text operation.

`resolvePackageFieldBinding` reports current, changed, missing, unsupported or deliberate override. Linked fields are current only when their current value equals both the last applied value and the formatted current fact. An override preserves the local value until deliberate reconnection; missing facts, definitions and fields still need attention. A metadata proposal never writes a draft or saves a revision.

`patchPackageBindingDraftFields` accepts qualified target/expected/value operations, owns its clone, validates the original and resulting draft and preserves embedded files. It validates all expected values before writing, disallows competing writes and advances a configured form's answer revision once. Header changes leave paragraph identities, selected-text anchors and citation locations intact; field comments retain their old context and resolve as changed. A caller must persist the edited draft and link metadata together in a reviewed package revision.

Suggestions retain every candidate with exact member/revision/target identity and descriptive captured provenance. They do not adopt a value, infer a person or read binary resources. Ambiguous legacy date strings are excluded. A stored source label or digest is descriptive evidence, never a live pointer.

All link strings, including orphaned and override expected values, receive export handling and privacy checks. Stale links block assembled PDF readiness; editable transfer can retain incomplete work with warnings. Metadata is limited to 256 KB per revision and 8 MB across retained revisions and review baselines. Ordinary revisions and review applications preserve links. Removing a bound fact requires explicit repair or detachment. Template capture refuses bound revisions until a clean starter has been prepared; it cannot silently reuse linked personal values.
