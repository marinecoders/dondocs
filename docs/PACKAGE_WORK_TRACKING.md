# Package work and next actions

In Packages, **Work and next actions** keeps a short coordination list with the saved action. Add a task, enter a responsible person and an optional due date, and link it to an existing document or saved requirement when useful. Names are entered labels; tasks do not assign account permissions.

Task dates use `YYYY-MM-DD`. A pending task is overdue only when its due date is before the current local calendar date. Tasks due today are not overdue.

## Save work

Changes stay in the editor until **Review task changes** and **Save task changes**. Review includes task titles, responsible people, dates and notes. Saving creates a child package revision and leaves older task states and captured documents available in history. **Discard task changes** restores the saved list.

Task completion is a manual coordination status. It does not fulfill missing evidence, resolve contradictory facts, accept feedback, authenticate a person or grant approval. Reopen a completed task by clearing its Complete checkbox and saving the change.

Linked items retain their exact identities. If a document or requirement is removed, the task shows an unavailable destination; it never moves to a similarly named item. Choose a new linked item or clear the link deliberately.

## Check the next action

Choose **PDF assembly**, **Start review**, or **Editable handoff**, then select **Check next actions**. The check inspects the saved revision and its actual operation prerequisites. It does not run on every keystroke. Save or discard task edits before checking.

The list prioritizes unresolved package checks, then overdue tasks, active review context and other pending work. Findings open the relevant saved document, requirement or shared value where that destination is available. Different operations can have different blockers: an editable handoff may carry an unfinished action that cannot yet produce a PDF.

Computed checks come from the existing intake, evidence, consistency, field-link and citation inspectors. PDF and editable-handoff inspection also uses the existing assembly readiness preparation. Missing or corrupt content remains unresolved. A task marked complete never removes those findings.

An active or closed review belongs to its captured revision. Task status and review lifecycle labels do not establish approval, and a retained PDF is not relabeled as a newer document.

Historical revisions and reviewer copies can be inspected but their tasks are read-only. Changing the selected package, revision or deployment settings invalidates an outstanding inspection or reviewed edit. Cancelled, stale and failed saves preserve the prior saved package.

## Transfer and limits

Editable transfer, package recovery and exact review baselines preserve the selected task metadata. Responsible people and notes travel with that content and are included in disclosure review. Reusable templates do not copy a case's work list into a new action.

A revision supports up to 100 tasks and 256 KB of task metadata. The editor presents 25 tasks or findings at a time. Retained task data across package revisions and review baselines is bounded to 8 MB.
